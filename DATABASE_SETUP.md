# Shared trips setup

1. Create a Supabase project. In SQL Editor, run `supabase/001_initial.sql` and then `supabase/002_shared_ledger.sql`. If the first migration was applied earlier, run only the second. The migrations enable row-level security and create a private 2 MB UPI QR bucket. The server checks authenticated trip membership before returning shared data.
2. Copy `.env.example` to `.env.local`. In Supabase, find your project URL, publishable key, and secret key. Put them in the corresponding fields. Keep the Supabase secret key and all provider keys in the server environment.
3. In the Supabase Google provider settings, copy the provider callback URL. Create a **Web application** OAuth client in Google Auth Platform and add that URL under **Authorized redirect URIs**. Add your app’s origin under **Authorized JavaScript origins**. If the Google consent screen is in Testing, add the Google accounts that will test joining trips to **Test users**. Back in Supabase, enable the Google provider and enter the client ID and secret. [Supabase Google sign-in setup](https://supabase.com/docs/guides/auth/social-signin/auth-google)
4. In Supabase Authentication → URL Configuration, set the Site URL to your app origin and allow its `/auth/callback` URL. For port 3001, use `http://localhost:3001/auth/callback`. Match `APP_ORIGIN` to the origin you open in the browser. Add the HTTPS equivalent for a deployment. [Supabase redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls)
5. Verify a sending domain in Resend. Set `RESEND_API_KEY` and `TRIPTRACK_INVITE_FROM` to your verified sender address, such as `Splittrack <trips@your-domain.example>`. Set `APP_ORIGIN` to the HTTPS origin that friends can open. The local shared app can create and copy an invite link for two browser sessions on one computer. The app reports email delivery as unavailable when the recipient-facing HTTPS origin or email settings are missing. [Resend sending domains](https://resend.com/docs/dashboard/domains/introduction)
6. Set `GEOAPIFY_API_KEY` for real venues. The expense map includes OpenStreetMap and Geoapify attribution. [Geoapify geocoding API](https://www.geoapify.com/geocoding-api/)
7. Restart Next.js, sign in at `/auth`, and create a trip. Enter a friend’s name and their Google email in **Members**. Open the invite with that same Google account and accept it. The friend can then view the same trip, expenses, and pins. Use the dashboard’s **Payment profile** to manage UPI details. If an invite fails to send, copy its link or resend it from the member row.

To run the fictional demo, keep the Supabase settings empty and use `npm run dev`. Click **Load five demo trips**. For a blank demo trip, set its destination to `Coral Bay` and try `Lantern Lodge` for an automatic pin or `Driftwood Cafe` for branch selection. Members and their entered emails stay in the local ledger in this mode.

For Vercel, configure the same environment values for the deployment, use its HTTPS origin for `APP_ORIGIN`, and add its auth callback in Supabase. The local file-based demo is intended for local judging.
